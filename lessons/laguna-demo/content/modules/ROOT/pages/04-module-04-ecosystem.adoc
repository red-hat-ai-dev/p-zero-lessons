== Exercise 3: Understand quantization formats

In the RedHatAI Models list, you will see several quantization suffix patterns:

[cols="1,3"]
|===
| Format suffix | What it means

| `-FP8-block`
| Block-wise FP8 quantization — weights quantized in small blocks; good balance of quality and compression on Hopper (H100) GPUs

| `-FP8-dynamic`
| Dynamic FP8 quantization — quantization scale computed at runtime per activation; slightly higher quality at cost of runtime overhead

| `-NVFP4`
| NVIDIA FP4 quantization — 4-bit weights for Blackwell (B100/B200/DGX Spark) GPUs; maximizes throughput on next-gen hardware

| (no suffix)
| BF16 full precision — unquantized mirror of the upstream model; requires full VRAM
|===

TIP: Choose the format that matches your hardware. H100 users: prefer `-FP8-block` for the best quality-per-VRAM tradeoff. Blackwell users: try `-NVFP4`. For the workshop, `RedHatAI/Laguna-S-2.1` (BF16) is served via vLLM's `--quantization fp8` flag, which performs FP8 quantization on load — functionally similar to a `-FP8-block` model.

== Module summary

* The `RedHatAI` HuggingFace organization (Enterprise, Verified) is the canonical source for Red Hat AI validated models — backed by IBM + Red Hat collaboration
* Monthly validated collections cover Nemotron, Qwen, Kimi, Inkling, Gemma, and other frontier model families
* Quantization formats (FP8-block, FP8-dynamic, NVFP4) are hardware-specific — match the format to your GPU generation
* For Laguna S 2.1, using `RedHatAI/Laguna-S-2.1` with vLLM `--quantization fp8` gives you the Red Hat AI model ID with on-load FP8 quantization until a pre-quantized Red Hat AI variant is published
